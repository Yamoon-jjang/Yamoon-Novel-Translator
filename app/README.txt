- 왜 버전을 올렸나: 폴더 번역으로 소설을 번역하면 확정 용어집과 인물 말투표가 만들어지지 않는다는 회원 제보.

  일반 낱말이면(小雪 = 가랑눈) 용어집에 들어가지 않음.

  주지 않음.

  그림만 있는 EPUB과 복제 방지(DRM)가 걸린 EPUB은 열지 않고 이유를 알려 줍니다.
- 폴더 번역에도 PDF·EPUB이 포함되며, 열 수 없는 파일은 그 파일만 건너뛰고 다음 파일로 갑니다. TXT 인코딩 설정은 PDF·EPUB에 쓰지 않습니다.
- 저장: TXT로 연 파일은 지금처럼 TXT만. PDF·EPUB으로 연 파일도 자동 저장은 .ko.txt(미완료 .ko.partial.txt, 출력 폴더·이어 번역 동일)이고,
  [결과 저장]에서만 TXT 또는 그 형식을 고를 수 있습니다. 원본 모양이 아니라 새로 짠 읽기용 파일입니다.

  · EPUB: 장 제목마다 장을 나누고 목차를 붙인 EPUB 3, 문단 간격 (파이썬 기본 기능으로 만듦, 글꼴은 전자책 앱의 한글 글꼴)
- 같은 폴더에 이름이 같은 TXT·PDF·EPUB이 있으면(책.txt / 책.pdf) 결과가 서로 덮어쓰지 않도록 PDF·EPUB 쪽은
  책.pdf.ko.txt / 책.epub.ko.txt로 저장합니다.
- 새 구성 요소: PDF 글자 추출용 pypdf(BSD-3-Clause, 순수 Python) 하나. PyMuPDF(AGPL)는 쓰지 않습니다. EPUB은 새 구성 요소가 없습니다.

번역 엔진
- API 설정 맨 위 "번역 엔진 순서"에서 Gemini / OpenAI / 로컬 LLM을 1~3개 체크하고 순서를 정합니다.

  · 막힌 문단(거부·서버 차단)은 문단 단위까지 좁힌 뒤 다음 엔진으로 넘깁니다.
  · 주 엔진의 한도 소진·키 오류·장애가 계속되면 그 파일의 남은 청크를 다음 엔진으로 이어 번역하고,
    10청크마다(config/app.json gemini_probe_every_chunks) 복구 여부를 확인해 돌아옵니다.
  · 기존 설정(Gemini + OpenAI 보조)은 자동으로 이어집니다. 기본 보조 순서는 로컬 LLM → OpenAI(비용 절약).
- 로컬 LLM: Ollama / LM Studio 등 OpenAI 호환 주소(기본 http://localhost:11434/v1/chat/completions)와 모델 이름만 입력.

  서버가 꺼져 있으면 작업을 멈추지 않고 그 파일에서는 건너뜁니다. <think> 추론 출력은 자동 제거합니다.
- 기본 Gemini 모델: Gemini 3.1 Flash Lite. 모델별 생각 단계 지원표(config/models.json thinking_levels)를 따르고,

붙여넣은 글 번역 (원문 탭)
- 원문 탭의 창에 글을 직접 붙여넣거나 고친 뒤 [번역 시작 / 계속]을 누르면 창의 내용 그대로 번역합니다.
  · 파일 없이: 아무 글이나 붙여넣고 바로 번역.
  · 파일을 연 뒤: 끝에 이어 붙이거나 일부를 고쳐도 됩니다. 원본 파일은 바꾸지 않고
    데이터 폴더의 paste\ 에 임시 원문(예: 책이름_수정_날짜.txt)을 만들어 번역합니다.
    확정 용어집·작품 메모는 그대로 쓰고, 이미 번역한 문단은 "번역 기억"으로 재사용해 새로 넣은 부분만 요청합니다.
- 끝나면 같은 창이 [번역 결과] 보기로 바뀝니다. [원문]/[번역 결과]로 오가고 [결과 복사]·[결과 저장] 가능.
- 폴더 작업 중에는 원문 창을 고칠 수 없습니다(읽기 전용).

번역 기억
- 같은 언어·용어집·작품 메모·언어 옵션·번역 지침으로 이미 번역한 청크와 원문이 완전히 같으면
  다른 작업이라도 요청 없이 재사용합니다.
  "처음부터 다시"를 누르거나 용어집·작품 메모·언어 옵션이 바뀌면 재사용하지 않습니다.
  모델·생각 단계·번역 방식은 기준에 넣지 않습니다(모델만 바꿔 남은 부분을 이어 번역할 수 있도록).
  다른 모델로 처음부터 다시 번역하려면 "처음부터 다시"를 누르세요.

- 확정 용어집 탭의 "번역 시작 시 먼저 자동 추출"(기본 켜짐): 파일·붙여넣은 글을 처음 번역할 때
  인명·용어 추출을 먼저 한 번(요청 1회, 보통 몇 초) 실행해 새 항목만 확정 용어집에 더한 뒤 번역을 시작합니다.
  이미 있는 항목은 바꾸지 않고, 같은 원문으로 "계속"할 때는 다시 추출하지 않습니다. 추가된 항목은 상태 / 오류 기록에 표시.
  실패해도 번역은 그대로 시작합니다. 폴더 작업(v2.5.8~)은 파일마다: 각 파일 독립 작품이면 파일마다 따로 추출해 그 파일에만,
  한 작품의 연속 파일이면 새 파일마다 새 이름만 폴더 용어집에 더함. 저장된 번역이 있는 파일은 그때 쓴 용어집으로 이어 가며
  다시 추출하지 않습니다. 폴더 번역 중에는 묻는 창 없이 기록에 남깁니다.
- 이전에 번역하던 파일(완료된 청크가 있음)을 이어 번역할 때 용어집이 비어 있으면 먼저 묻습니다:
  [추출 후 처음부터 번역] / [용어집 없이 이어서 번역] / [취소]. 용어집이 바뀌면 이전 번역을 이어 쓸 수 없기 때문입니다.
  용어집이 이미 있으면 그대로 이어서 번역합니다. 추출하지 않은 경우에도 그 이유를 상태 / 오류 기록에 한 줄로 남깁니다.
- 같은 원문이라도 용어집을 비웠다면 다시 추출합니다.
- 엔진 순서의 첫 번째 준비된 엔진이 추출합니다(로컬 LLM만 쓰면 로컬 LLM이 추출).

로컬 LLM 속도 (Ollama)
 - 로컬 LLM 보조 엔진 등록만으로 사전 예열하지 않습니다. 첫 실제 Ollama 번역 요청에서 로딩하고 요청 후 5분 동안만 유휴 모델을 유지(<code>keep_alive=5m</code>)해 재사용합니다.
 - 마지막 요청으로부터 5분 동안 Ollama가 사용되지 않으면 자동 해제됩니다. LM Studio에는 Ollama 설정을 적용하지 않으며, 별도 도구의 요청은 Ollama 유지 시간을 갱신할 수 있습니다.
 - 번역 프롬프트·청크 분할·내용 정책 분류·미완료 복구·모델/엔진 우선순위는 변경하지 않습니다.

- Ollama 주소(포트 11434)는 Ollama 전용 방식(/api/chat)으로 요청합니다.
  · 추론(생각) 출력 끄기(기본): Qwen3 등은 답 전에 긴 생각을 먼저 생성해 몇 배 느려지므로 끕니다.
  · 컨텍스트 길이 12,288 토큰(기본): 한 번 요청(지침 약 3천 + 앞 문맥 + 원문 + 번역문)이 약 9천~1만 토큰인데,
    Ollama 기본값 4,096으로는 지침이 잘려 품질이 떨어집니다. 고정값이라 요청마다 모델을 다시 불러오지 않습니다.
  · 작품 메모가 길거나 품질 우선 모드라 요청이 설정값보다 크면 그 요청만 자동으로 늘려(최대 32,768) 지침이 잘리지 않게 합니다.
  · 연결 테스트에 생성 속도(토큰/초)가 표시됩니다. 한 자리 수라면 모델이 그래픽카드 메모리에 다 들어가지 않은 것입니다.
- 16GB 그래픽카드: 27B Q4(약 16GB 이상)는 일부가 CPU에서 돌아 느립니다. 속도가 필요하면 14B 이하 Q4~Q6 모델을 권장.
- LM Studio 등 다른 주소는 OpenAI 호환 방식 그대로입니다.

    같은 작업을 다시 시작하면 그 청크만 재시도합니다. 상세 위치는 UI의 미완료 목록 탭에 표시됩니다.
- PROHIBITED_CONTENT 차단은 문단 단위까지만 격리합니다(문장으로 쪼개 필터를 빠져나가게 하지 않음).
  단일 문단으로 격리된 차단 문단은 엔진 순서의 다음 엔진(로컬 LLM·OpenAI)으로 보냅니다(config/app.json의 fallback_on_policy로 끌 수 있음).
- 문단 분리 수정: 빈 줄이 있는 TXT에서 빈 줄 사이 전체(보통 한 장 전체)를 문단 하나로 묶던 문제 수정.
  줄바꿈 한 번으로 나뉜 실제 문단을 각각 문단으로 처리합니다(원문 배치는 그대로 복원).
  기존에는 차단 1건이 장 전체를 원문으로 남겼습니다.
- 줄바꿈 없이 한 줄로 된 긴 장은 차단 시 약 300자(영어 800자) 크기까지 좁혀 격리하고, 그보다 잘게는 쪼개지 않습니다.
- 거부 문구 감지 확대(“I'm sorry, but I can't…”, “번역해 드릴 수 없습니다”, “번역하기 어렵습니다” 등).
- 원문에 없는 “(생략)”, “(중략)”, “[검열]” 같은 임의 생략 표기, 문장째 원문을 남기는 회피 번역을 감지해 재요청합니다.
- OpenAI 응답이 incomplete(콘텐츠 필터/토큰 한도)인데 일부 텍스트가 있으면 잘린 번역을 성공으로 받던 문제 수정.

프롬프트
- 성인 독자 대상 완역 범위(SCOPE)를 명시: 성인 간의 성적 묘사·폭력·범죄·비속어 등은 다른 문장과 똑같이 번역.
- 유일한 제외: 미성년자로 제시된 인물이 관련된 성적 내용. 해당 문단만 ⟦NT_SKIP⟧ 표식으로 받아 원문을 유지하고
  나머지 문단은 정상 번역합니다(청크 전체 거부 방지). 이 표식은 결과 파일에 들어가지 않습니다.
- 언어별 성인 장면 표현 규칙 보강: 일본어 신음/♡ 기호/의성어, 중국어 완곡어·플랫폼 검열 자리표시, 영어 비속어 수위.
- 공통 문체 규칙: 괄호 원문 병기 금지, 서술 해라체 일관, 원문 잔류 금지.
- 중국 플랫폼/신조어, 일본어 담화 표지 등의 문맥 판별형 용어 안내 추가.
- 프롬프트 버전 변경(9→10)으로 기존 진행 중 작업은 새 작업으로 인식되어 처음부터 번역됩니다.

  공급자 약관 위반(키·계정 정지 위험)이라 사용하지 않습니다.

Novel Translator 0.11.0 · Literary Continuity Candidate

목적
- TXT 소설 전용 번역기
- 일본어 / 중국어 / 영어 → 한국어
- 단일 TXT 또는 폴더의 여러 TXT를 한 파일씩 순차 번역
- 원문의 문체·관계·수위·의미를 가능한 한 충실히 유지
- 합법적인 성인 문학의 성적 표현·욕설·폭력 표현을 단지 노골적이라는 이유로 임의 순화/삭제하지 않음
- 공급자의 비조절 핵심 정책을 우회하지 않음. 거부가 발생하면 번역 작업 전체가 망가지지 않도록 별도 복구/부분결과 흐름으로 처리

최종 사용자 배포 원칙
- 최종 사용자는 Python이나 pip를 설치할 필요가 없어야 함.
- 첫 Windows 배포 형식은 PyInstaller ONEDIR portable 폴더를 기본으로 함.
- 사용자는 NovelTranslator.exe를 실행함.
- Qt DLL/플러그인은 _internal에 포함되고 config/ 및 profiles/는 EXE 옆에 복사되어 일부 정책/모델/프롬프트 설정을 재빌드 없이 조정할 수 있게 함.
- 개발용 requirements*.txt는 최종 사용자가 설치하기 위한 파일이 아님.

처음 사용하는 순서
1. NovelTranslator.exe 실행.
2. 우측 상단 “API 설정”에서 Gemini API 키를 추가.
   - Gemini 키는 최대 10개까지 등록 가능. 목록 위쪽 키가 우선이며 정상인 1번 키를 계속 사용함.
   - 같은 Google Project에서 만든 키들은 같은 “프로젝트 그룹” 이름으로 지정.
   - 서로 다른 Project라면 서로 다른 그룹명 사용.
   - 저장된 키의 전체 문자열은 이후 다시 표시하지 않음.
   - 원하는 키를 선택하고 “선택 키 연결 테스트”로 실제 연결 확인 가능.
   - 맨 위 "번역 엔진 순서"에서 Gemini·OpenAI·로컬 LLM 중 쓸 엔진과 순서를 정함. OpenAI·로컬 LLM은 각 탭에서 키·모델 설정.
3. “TXT·PDF·EPUB 파일 선택” 또는 “폴더 선택”. PDF·EPUB은 글자만 꺼내 TXT와 똑같이 번역.
4. 원문 언어(일본어/중국어/영어)를 선택.
5. 필요하면 TXT 인코딩을 수동 지정. 기본은 자동 감지.
6. 언어별 설정 확인.
7. 작품 전체에서 반드시 유지해야 하는 인물 관계/말투는 “작품 메모”에 입력.
8. 반드시 고정해야 하는 이름/전문 용어는 “확정 용어”에 입력 또는 TSV로 가져오기.
9. 번역 방식 선택:
   - 균형(권장): 기본 청크/문맥(앞 문맥 3,000자), Gemini 생각 단계 low
   - 품질 우선: 더 작은 청크와 긴 문맥(5,000자), 생각 단계 medium
   - 속도 우선: 더 큰 청크와 짧은 문맥, 생각 단계 low
   (Gemini 3.1 Flash Lite처럼 생각 단계를 지원하지 않는 모델에는 보내지 않음)
10. 준비 상태가 모두 체크되면 “번역 시작 / 계속”.

단일 파일 결과
- 정상 완료: <원본이름>.ko.txt
- 일부 미완료/거부/중지: <원본이름>.ko.partial.txt
- 미완료 상세: UI의 미완료 목록 탭(별도 파일 없음). 나중에 완료되면 .ko.partial.txt는 정리.
- 출력 폴더를 지정하면 원본 옆 대신 그 폴더에 저장(앱 전체 설정, 재시작 후에도 유지).
- PDF·EPUB으로 연 파일도 같은 이름 규칙(.ko.txt / .ko.partial.txt). 읽기용 PDF·EPUB은 [결과 저장]에서 형식을 고를 때만 만듦.
- 원본 TXT는 수정하지 않음.
- 같은 결과 파일에 수동 수정 내용이 존재할 수 있으므로 자동 교체 전 .before_날짜시간.bak 백업을 남김.

폴더 작업
- “여러 파일 동시 번역”이 아니라 목록 순서대로 하나씩 완전히 처리한 뒤 다음 파일로 진행.
- 기본 결과 위치: 선택한 원본 폴더/한국어_번역/ (출력 폴더를 지정하면 그 폴더)
- 하위 폴더 포함 선택 가능.
- 원래 하위 폴더 구조 보존.
- 결과물(.ko.txt/.ko.partial.txt, 이전 버전의 .ko.failed.txt)과 번역_요약.txt는 다음 검색에서 원문으로 다시 선택하지 않음.
- “각 TXT 독립 작품”: 파일 사이에 짧은 문맥을 전달하지 않음.
- “한 작품의 연속 파일”: 앞 파일이 정상 처리된 경우 마지막 문맥을 다음 파일에 전달.
- 앞 파일이 완료·부분 완료이면 마지막 문맥을 전달하고, 읽기 오류로 건너뛴 파일 다음은 문맥 없이 시작.
- 확정 용어집 · 인물 말투표(v2.5.8): 독립 작품은 파일마다 따로 만들어 그 파일에만, 연속 파일은 폴더 것을 함께 쓰며 새 이름 ·
  새 인물 짝만 더함. 저장된 번역이 있는 파일은 그때 쓴 용어집으로 이어 감(내용으로 판정, 이름 변경 · 복사 무관).

언어 프로필
- 언어 변경은 단순 UI 표시가 아니라 전체 프로필 변경임.
- 일본어: 생략 주어, 私/僕/俺 계열 화법, 경어/반말, 호칭, 말끝, 의성어, 독백, 방언/역할어, 관계 변화 등을 고려.
- 중국어: 간체/번체, 인명/별칭, 친족·사회·문파 호칭, 성어, 인터넷 표현, 무협/선협/시대물 용어, 문법적 생략 등을 고려.
- 영어: 대명사 과잉 반복 방지, 시제/상, 자유간접화법, dialogue tag, 속어/방언/고어, 직함/호칭, 긴 문장 재구성 등을 고려.
- 문맥에 따라 뜻이 달라지는 일반 단어는 기본 강제치환하지 않음. 사용자가 확정 용어로 지정한 항목만 강제 우선.

성인 문학 처리
- 번역 요청은 “기존 작품의 변환/번역”으로 명확히 프레이밍.
- 원문보다 성적 내용을 새로 만들거나 강화하지 않음.
- 원문이 직접적이면 직접적인 수준을, 완곡하면 완곡한 수준을 유지하도록 지시.
- Gemini가 공식적으로 제공하는 조절 가능한 safety 설정은 providers.json에서 번역 용도에 맞게 구성.
- 공급자의 비조절 정책 거부를 금칙어 분해/은폐 방식으로 우회하지 않음.
- 조절 가능한 safety/응답 형식 문제 시: 번역임을 다시 명확히 하는 1회 재시도 또는 문단/문장 단위 청크 축소 → 여전히 실패하면 해당 위치를 원문과 함께 partial 결과에 보존하고 다음 청크 진행.
- PROHIBITED_CONTENT 등 공급자 핵심 policy 차단은 원문을 변형하지 않고 문단 단위까지만 좁혀 격리한 뒤,
  그 문단만 다음 엔진에 맡기고, 그래도 안 되면 원문으로 남겨 partial 위치로 기록하고 다음 청크로 진행.

무료/유료 프로젝트 키 사용 (v1.61 호환 확장)
 - Gemini API 설정의 각 프로젝트 그룹에 무료 / 유료 / 미지정 등급을 기록할 수 있습니다. 등급은 사용자가 직접 확인하여 지정합니다.
 - 서로 다른 무료 프로젝트 A, B와 유료 프로젝트 C의 키를 각 1개씩 A → B → C 순서로 등록하는 구성을 권장합니다.
 - 앞 프로젝트의 한도 제한 시 뒤의 사용 가능한 프로젝트로 자동 전환합니다. 유료 프로젝트로 전환할 때 매번 확인하지 않으며 실제 과금이 발생할 수 있습니다.
 - 유료 사용을 완전히 막으려면 유료 키의 사용 체크를 해제해야 합니다. 무료/유료 등급 표시 자체는 키 사용을 차단하지 않습니다.
 - 번역 상태에 사용 중인 프로젝트 그룹과 무료/유료 등급을 보여 줍니다. API 키 비밀 문자열은 표시하지 않습니다.
 - 프로젝트별 요청 사용량과 유료 요금 추정치를 구분하되 실제 청구액은 Google AI Studio에서 확인해야 합니다.
 - 기존 키의 등급 기본값은 미지정이며 키 우선순위·재시도·번역 저장/복구 기능은 유지합니다.

복수 API 키/장애 처리
- 복수 Gemini 키 저장, 이름 변경, 프로젝트 그룹 지정, 개별 사용/해제, 개별 삭제 지원.
- Windows 배포에서는 키 저장에 Windows DPAPI 사용.
- 로그/결과 파일에 전체 키 문자열을 기록하지 않음.
- 같은 프로젝트 그룹 키는 429/쿼터 시 동일 제한을 공유한다고 가정하여 무작정 회전하지 않음.
- 다른 프로젝트 그룹의 정상 키가 있으면 사용할 수 있음.
- 인증 실패/차단/유출로 판정된 키만 자동 비활성화하고 상태를 저장.
- 429/쿼터는 키 영구고장으로 저장하지 않음.
- adaptive RPM: 보수적으로 시작해 성공이 지속되면 조금씩 증가하고 429 시 즉시 감속.
- 파일/청크 요청 동시성은 기본 1. 안정성과 문맥 일관성을 우선.

중단/재개
- 청크 성공 시 SQLite에 즉시 저장.
- 사용자가 중지하거나 API 전체 장애로 안전 일시정지될 때 즉시 .ko.partial.txt 생성.
- 비정상 종료 후 REQUESTING 등 중간 상태는 다음 실행에서 PENDING으로 복구.
- 이어 번역에서는 완료된 청크를 모두 그대로 쓰고, 미완료(실패) 청크와 부분 완료 청크만 다시 요청함.
  부분 완료 청크는 원문으로 남은 문단만 보내고 이미 번역된 문단은 유지. 다시 실패해도 이전 부분 번역은 지우지 않음.
- 프롬프트/확정 용어/작품 메모/언어 옵션/청크 조건이 바뀌면 fingerprint가 달라져 오래된 완료 결과를 조용히 재사용하지 않음.
  모델·생각 단계·보조 엔진 설정은 fingerprint에서 제외(모델을 바꿔 미완료 부분만 이어 번역 가능).

결과 무결성
- 문단마다 내부 ID를 사용해 모델의 문단 누락/순서 변경을 검출.
- HTTP 200이어도 빈 응답, 지나치게 짧은 응답, 원문 그대로 반환, 문단 ID 불일치, 잘린 출력, 거부 문구형 응답 등을 검증.
- 실패 문단은 최종 파일에서 조용히 삭제하지 않음. partial 결과에 상태 표시 + 원문을 그대로 남김.
- 원문의 들여쓰기와 빈 줄 separator를 가능한 한 보존.
- 매우 긴 단일 문단도 재시도 시 더 작은 조각으로 나눌 수 있음.

현재 지원 Provider
- 기본 Provider: Google Gemini.
- Gemini 키 풀: Provider당 최대 10개 신규 등록, 사용자 지정 우선순위, Project 그룹 인식.
- 정상인 최우선 Gemini 키를 계속 사용하며 단순 round-robin으로 예비 키를 소모하지 않음.
- 키 자체가 invalid/leaked/blocked이면 다음 예비 키로 전환.
- 429/쿼터가 Project 단위 문제이면 같은 그룹의 다른 키를 무작정 두드리지 않고, 독립 Project 그룹을 우선 사용.
- 보조 Provider: 공식 OpenAI Responses API. 사용자가 API 설정에서 명시적으로 켠 경우에만 동작.
- Gemini의 예비 키/독립 Project/정상 재시도/청크 복구가 먼저이며, 그 뒤에도 진행할 수 없는 core POLICY 이외의 오류에서만 OpenAI fallback을 사용.
- PROHIBITED_CONTENT 등 명시적 core POLICY 거부는 Provider를 바꿔 우회하지 않음.
- fallback으로 번역된 청크는 SQLite에 provider=openai 및 fallback_used=1로 기록하여 나중에 구분 가능.

Alpha 0.8 추가 보강
- 한 작품의 연속 파일 모드는 앞 파일이 부분완료이거나 파일 읽기/인코딩 오류이면 다음 파일로 넘어가지 않음. 문맥 구멍을 만든 채 후속 장을 번역하는 것을 방지.
- 큰 청크 안에서 문단 하나만 심하게 축약되거나 일본어/중국어 원문이 거의 그대로 남는 경우를 문단 단위로 추가 검출.
- 언어 경고용 감지는 현재 선택된 프로필에 끌려가지 않도록 UTF-8/CP932/GB18030/Big5/CP1252 후보를 독립 비교.

빌드 전 자동 검사
개발/빌드 머신에서:
  python tests/prebuild_gate.py
  python -m pytest -q
  python tests/stress_audit.py
  python -m compileall -q .

Windows 빌드:
  build_windows.bat

build_windows.bat는:
- prebuild gate 실행
- 전체 pytest 회귀 테스트 실행
- 실제 TranslationWorker 경로의 Qt-free 종단 시뮬레이션 실행
- 20,000 요청 429/503 장애주입 stress audit 실행
- 750개 무작위/적대적 TXT 레이아웃·부분실패 fuzz audit 실행
- Python compileall 검사
- PyInstaller ONEDIR 빌드
- config/profiles를 EXE 옆에 복사
- 만들어진 NovelTranslator.exe --self-test 실행
- NovelTranslator.exe --engine-self-test로 패키징된 Worker→SQLite→검증→결과 TXT 경로를 네트워크 없이 종단 실행
- Windows 기본 Qt platform(qwindows)으로 NovelTranslator.exe --gui-self-test를 실행해 실제 QApplication/MainWindow 생성 확인
- 완성된 portable 폴더 전체를 공백+한글이 포함된 임시 경로로 복사한 뒤 self-test / engine-self-test / gui-self-test를 다시 실행하여 이동 배포와 Unicode 경로를 검증
- ONEDIR 배포에서는 EXE 옆 config/와 profiles/가 누락되면 _internal 사본으로 조용히 대체하지 않고 자체점검 실패로 처리
순서로 하나라도 실패하면 즉시 빌드를 중단함.

빌드 후 반드시 할 Windows smoke test
1. 새 폴더에 portable 결과 전체를 복사 후 최초 실행.
2. --self-test PASS 및 --gui-self-test PASS 확인.
3. 일반 실행에서 qwindows.dll/plugin 오류 없이 UI가 뜨는지 확인.
4. API 키 2개 이상 추가/저장/재실행/개별 삭제/비활성/재활성 확인.
5. 실제 Gemini 연결 테스트.
6. 일본어 CP932, 중국어 GB18030, 영어 UTF-8/CP1252 소형 TXT 각각 실제 1회 번역.
7. 단일 파일 결과명/partial/failed 확인.
8. 폴더 배치 3~10개 파일 순차 진행 확인.
9. 번역 중 중지 → partial 생성 → 앱 종료 → 재실행 → 계속 확인.
10. 네트워크 끊김/잘못된 키/429 가능한 시험 환경에서 UI가 죽지 않고 이유를 표시하는지 확인.
11. 번역 중 창 닫기 요청 후 QThread 관련 강제종료가 없는지 확인.
12. 원본 폴더 쓰기 권한이 없는 경우 LocalAppData exports fallback 확인.
13. 결과 파일을 수동 수정한 뒤 재번역할 때 .before_*.bak 보존 확인.

현재 내부 QA 상태
- Pre-EXE source gate: 회귀 테스트/빌드 게이트 PASS (정확한 개수는 해당 후보의 pytest 출력 기준).
- Production Worker Qt-free end-to-end audit PASS (정상 완료/부분 실패/중지·재개/core-policy 비우회/초장문 선제분할).
- 20,000 logical requests with recurring 429/503 failure injection PASS.
- 750 adversarial/random TXT layout and partial-render fuzz cases PASS.
- Python compileall / JSON / runtime resource / secret-pattern / UI signal-slot static gates PASS.
- 현재 환경은 Linux이고 PySide6/Windows GUI 런타임이 없으므로 실제 Windows qwindows.dll·DPAPI·PyInstaller 실행은 첫 Windows portable build에서 검증해야 함.
- 따라서 이 버전은 “첫 EXE 빌드 후보”이며 배포 완료본은 아님. 첫 Windows build가 `--self-test`, `--engine-self-test`, `--gui-self-test`를 모두 통과한 뒤 실제 Gemini 소형 TXT 3개(일/중/영)를 번역해 다음 단계로 승격함.

로컬 Windows에서 Python/pip를 사용할 수 없는 경우
- `.github/workflows/windows-portable.yml`은 수동 실행 가능한 Windows CI 빌드 경로입니다.
- 깨끗한 Windows runner가 requirements-build.txt를 설치하고 build_windows.bat의 전체 게이트를 실행한 뒤 portable ZIP을 artifact로 만듭니다.
- 이 과정에는 실제 Gemini API 키가 필요하지 않으며 소스/설정에 API 키를 넣지 않습니다.
